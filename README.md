# Pantry Chef AI (Fridge-to-Recipe)

Type what is in your fridge and get a structured recipe from Google Gemini. The app turns the model's JSON into an interactive cooking tool. It is not a chatbot.

**Stack:** React (hooks) + Vite + Tailwind CSS v4 + lucide-react, FastAPI backend, Google Gemini API.

## Features
- Free-form ingredient input, quick-add pantry chips, and a full Pantry Drawer
- Preferences: diet, cook time limit, skill level
- Recipe card with prep/cook time, difficulty, calories and dietary tags
- Scalable servings (1x to 4x) with live ingredient amounts
- Ingredient substitutions shown per ingredient
- Steps you can check off, with per-step cooking timers and a chime
- Save recipes to a Cookbook (localStorage)
- Raw JSON tab to inspect what the model returned
- Offline Mock Mode for testing without the API
- Loading skeleton, error and empty states, responsive layout
- Offline Mock Mode shows one fixed sample recipe so the UI can be tried without an API key. It does not use your ingredients

## Setup

You need Python 3.10+ and Node 18+.

1. **Get a free Gemini key** at https://aistudio.google.com/apikey

2. **Backend** (terminal 1, port 8000):
   ```
   cd backend
   python -m venv .venv
   .venv\Scripts\activate           # Mac/Linux: source .venv/bin/activate
   pip install -r requirements.txt
   copy .env.example .env           # Mac/Linux: cp .env.example .env
   ```
   Open `.env` and paste your key:
   ```
   GEMINI_API_KEY=your_key_here
   GEMINI_MODEL=gemini-3.1-flash-lite
   ```
   Then start the server:
   ```
   uvicorn main:app --reload --port 8000
   ```
   Check `http://localhost:8000/api/health`. It should show `"key_configured": true`.

3. **Frontend** (terminal 2, port 5173):
   ```
   cd frontend
   npm install && npm start
   ```
   Open http://localhost:5173

Run both terminals at the same time. The backend must be running for live recipes. Offline Mock Mode works without it.

## How it works
1. The browser sends the ingredients and preferences to `POST /api/recipe` on the FastAPI backend.
2. The backend builds the prompt and calls Gemini with `responseMimeType: application/json`. The API key stays on the server and never reaches the browser.
3. The backend extracts the JSON, validates it with Pydantic, and returns a clean recipe object.
4. The frontend runs its own `parseAndValidateRecipe` check, fills in safe defaults, and renders interactive components.

## How bad AI output is handled
| Problem | Handling |
|---|---|
| Malformed JSON, extra text or markdown around it | The parser takes the text between the first `{` and the last `}` |
| Wrong shape or missing fields | Pydantic validation, safe defaults for optional fields, one automatic retry, then a clear 502 error |
| Fractions like `"1/2"` or plain-string steps | Normalised in validators instead of failing |
| Empty or blocked reply | Treated as bad output, retried once, never crashes |
| Input that is not food | Model returns `{"error": ...}`, shown as a friendly 422 message |
| Slow model | 90 second timeout with a clear message |
| Rate limit (429) and service errors | Specific messages with the provider's detail |
| Backend not running | "Can't reach the server" message |
| Stale responses | Each request has an id and an `AbortController`. Older responses are ignored, so they can never overwrite a newer one |

Every error state has a message, and Offline Mock Mode is offered as a fallback.

## Known limitations
- Amounts, calories and substitutions come from the model and can be inaccurate. There are no allergy or nutrition checks.
- Serving scale uses fixed 1x to 4x steps, not custom values.
- Substitutions are displayed as suggestions and cannot be applied to the recipe yet.
- Saved recipes are matched by title, so two recipes with the same title overwrite each other in the Cookbook.
- No streaming responses, authentication, tests or deployment.
- Backend CORS allows only `http://localhost:5173`.
- Gemini model names change often. Set `GEMINI_MODEL` in `.env`. During development `gemini-3.8-flash` took about 19 seconds for a trivial prompt because of its thinking step, so the default is `gemini-3.1-flash-lite` (about 1.5 seconds).

## Troubleshooting
| Symptom | Fix |
|---|---|
| `key_configured: false` | `.env` must be inside `backend/`, named exactly `.env`, with no quotes around the key. Restart uvicorn |
| `Could not import module "main"` | Run uvicorn from inside `backend/`, next to `main.py`, with the venv active |
| "AI service error (404)" | The model name is retired or wrong. Update `GEMINI_MODEL` and restart |
| "took too long to respond" | Use a lighter model such as `gemini-3.1-flash-lite` |
| Page unstyled | Run `npm install` again and check `vite.config.js` includes the Tailwind plugin |
